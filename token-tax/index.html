lipi · the token tax

The same sentence, up to 13.7× the tokens.

AI models read, write, time and bill text in tokens. Their tokenizers were built mostly on English, so the same sentence in an Indian language takes far more of them. On GPT-4o, Odia needs 4.99× the tokens of English, and Santali 13.7×. lipi measures that tax for 24 Indian languages and 15 tokenizers, then removes it from an open model.

Why it matters

A token count is not a price, since every API sets its own. It is how much text fits in a model's memory and how many steps the model takes to write an answer. Measured on Qwen 2.5 0.5B on one T4 GPU:

7.0× faster

Writing an Odia sentence: 8.37 s with Qwen's own tokenizer, 1.19 s with lipi-Indic. English takes 0.83 s.

116 → 881

Odia sentences that fit in a 32K-token context window, before and after.

3.40 s → 0.088 s

Reading a 3,000-character Odia document before the first word of the answer (5,923 tokens → 650).

Where the tax comes from. Two things. Most tokenizers have few tokens for Indian scripts, so words fall apart into pieces or raw bytes. And the pre-tokenizer of GPT-4, Llama 3 and Qwen splits words at every vowel sign before the vocabulary is even consulted, so however large their vocabulary, they cannot write Odia in fewer than 2.33× the tokens of English.

The fix. lipi-Indic changes that splitting rule for Indian scripts only and adds 96,000 tokens learned from text in all 24 languages to Qwen 2.5. Every existing token keeps its id, so English and code are tokenized exactly as before.

Use the tokenizer Code, raw results, method

Method. FLORES-200 devtest, 1,012 sentences per language (Meta, CC BY-SA 4.0; the example sentences above are from it). Tax = tokens for a language ÷ tokens for English, on the same tokenizer. Speaker weights: Census of India 2011. Google publishes no Gemini tokenizer; the “Gemini” figures are Gemma 3's tokenizer, which third-party ports report to be the same model, and were not checked against Google's countTokens. The live demo loads GPT-4o's tokenizer (o200k_base, Xenova/gpt-4o), Qwen/Qwen2.5-0.5B and Shakhtar-Sankur/lipi-indic-96k from Hugging Face with transformers.js.
