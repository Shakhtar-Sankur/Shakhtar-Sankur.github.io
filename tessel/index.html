tessel · a tile language and compiler

one kernel, three chips.

Designed, built and measured by Sankur KunduOpen source (Apache-2.0) · page updated 15 Oct 2026

Kernels are written against tiles, small blocks of values, and the compiler decides which thread holds which element. The same kernel compiles to CUDA for NVIDIA tensor cores, to Metal for Apple GPUs and to Pallas for TPUs, and is fast enough to run an LLM at vLLM's speed.

1.00×cuBLAS on fp16 GEMM at 1024³ and 2048³; 1.04× at 4096³ (0.71× before swizzling shared memory)
1.05×vLLM 0.30's throughput serving TinyLlama-1.1B, 32 requests on a T4; generations identical
1.3–1.9×Faster than PyTorch's scaled_dot_product_attention on causal attention, sequence 512–4096
3 targetsCUDA (tested on a T4); Metal and Pallas compiled and checked in CI
01 · How it works

Layouts decide everything

Every tile gets a linear layout, as in Triton, and the code generator lowers it to the instructions each chip wants.

CUDA for tensor cores

ldmatrix, mma.sync, XOR-swizzled shared memory and software-pipelined loads, tuned on the GPU it runs on and compiled at run time with NVRTC.

Metal and Pallas

The same kernels compile to the Metal Shading Language and to Pallas, where range analysis must prove every block access in bounds or the kernel is refused.

Checked four ways

CI runs every kernel against a reference interpreter on an emulator of the CUDA execution model, compiles it with NVRTC, runs Pallas's TPU interpret mode and compiles with Apple's Metal compiler.

02 · An LLM on tessel

Token for token with vLLM

An LLM engine whose every GPU operation is a tessel kernel: fused QKV projection, rotary embeddings, a paged KV cache, grouped-query attention, SwiGLU, continuous batching, packed prefill and CUDA graphs.

vLLM 0.301798 tok/s
tessel1884 tok/s

TinyLlama-1.1B, 32 requests at once on a Tesla T4 (session 2; session 1: 1858 vs 1764). With 8 requests tessel reaches 0.94–0.99× vLLM. Generations identical to vLLM's.

tessel's speed is the median, over 4 rounds, of its speed relative to the fastest other engine timed in the same round (above 1 is faster). Times are medians of each round's medians, so the columns need not divide exactly: the T4 throttles as it heats. cuBLAS is torch.matmul with fp32 accumulation, as tessel.

What tessel adds

A compiler, not a wrapper

The ideas behind Triton, rebuilt from the language up and taken to three kinds of hardware.

  1. Linear layouts, from scratch

    A typed tile IR where every tile has a linear layout, lowered to tensor-core instructions.

  2. Vendor-level GEMM

    Matches cuBLAS on fp16 GEMM after XOR swizzling and software pipelining.

  3. Portable by construction

    One kernel compiled to CUDA, Metal and Pallas, with bounds proved for TPUs.

  4. An LLM engine on top

    Serves TinyLlama at 1.05× vLLM's throughput, with identical generations.

Where it falls short

tessel has not yet been timed on a TPU or an Apple GPU: Metal and Pallas output is compiled and checked in CI, but not benchmarked. With 8 concurrent requests the LLM engine reaches 0.94–0.99× vLLM.
