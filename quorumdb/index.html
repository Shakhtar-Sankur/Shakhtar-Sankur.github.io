quorumdb · distributed SQL

zero safety violations.

Designed, built and measured by Sankur KunduOpen source (Apache-2.0) · page updated 15 Oct 2026

A distributed SQL database that psql connects to, built one proven layer at a time: a crash-safe LSM storage engine, Raft consensus, a sharded multi-Raft store that splits and rebalances itself, and serializable transactions across machines. Every layer is tested the way FoundationDB is.

01 · The stack

Built one proven layer at a time

Each layer is finished only when its own checker passes under random crashes, partitions and clock skew.

Storage and consensus

A crash-safe LSM storage engine under Raft consensus, and a sharded multi-Raft store that splits and rebalances itself.

Transactions

ACID transactions across machines at snapshot and serializable isolation, protocol model-checked in TLA+.

SQL

The PostgreSQL wire protocol: psql connects, with joins, aggregates, EXPLAIN and serializable transactions.

02 · Testing

Every run replays from one seed

Deterministic simulation, as FoundationDB pioneered: one seed replays a whole run of random work, crashes, partitions and clock skew exactly, and a checker proves every history linearizable or serializable.

610,064 crashes

Across 10,000 simulated clusters and 198.7 million messages, 22.9 million of them lost: zero safety violations.

15 / 15 planted bugs

From torn log tails to the Raft paper's Figure 8, every planted bug is caught; the method found 6 real bugs before release.

Time-travel debugger

Steps any simulated Raft cluster event by event, and backward by replay.

What quorumdb adds

Correctness you can replay

The verification methods of FoundationDB and AWS, applied to a database built from scratch.

  1. Deterministic simulation

    10,000 clusters, 610K crashes, every run replayable from one seed.

  2. Model-checked protocol

    The transaction protocol in TLA+: 337K states, zero violations.

  3. Bugs found before users

    15 of 15 planted bugs caught and 6 real bugs found before release.

  4. Real SQL on top

    PostgreSQL wire protocol and serializable transactions under a TPC-C-derived load.

Where it falls short

Throughput is measured with one terminal on a TPC-C-derived benchmark, not an audited TPC-C run, and quorumdb has not been compared with production databases under the same load.
